# Phase 09: Krait Integration

## Goal

Make Krait the primary developer surface for KIR inspection, KRB cartridge
preview, portable diagnostics, and source-aware debugging.

## Current State

Krait can preview native app hosts and has a cartridge panel that currently
shells out to the older KRB emission path. It can inspect nodes, strings,
imports, and opcodes for loaded cartridges.

## Target Design

Krait should use root Kryon tooling:

- `k2ir` for compiler inspection and diagnostics
- `k2b` for portable cartridge preview
- `k2c` for native app-host preview
- KRB runtime APIs for node/source-map inspection
- interpreter hooks for stepping portable logic

Krait should not own KRB capture or rendering correctness. Kryon tooling owns
preview rendering and PNG verification.

## Implementation Phases

1. Replace Krait cartridge generation with `k2b`.
2. Add a KIR panel that loads `.kir` or runs `k2ir` for the current source.
3. Show KRB loader diagnostics, required imports, and capability availability.
4. Use KRB source maps to jump from rendered nodes to `.kry` source.
5. Add portable logic stepping once KRB runtime supports interpreted KIR.

## Tests And Acceptance

- Krait can preview a KRB generated by root Kryon `k2b`.
- Krait can show KIR for the current `.kry` file.
- Missing imports are visible in the cartridge panel.
- Source-click inspection works through KRB source maps.

## Risks

- Krait vendors Kryon, so source-of-truth changes must land in root Kryon first
  and then update the vendored submodule pointer.
