Features

One source, every platform

The runtime owns the whole UI lifecycle: build the widget tree, reconcile state, layout nodes, route input, render, and draw overlays. You describe intent; Kryon handles ordering, focus, inspection, and overlay behavior.

Declarative .kry source

Pages and reusable widgets stay in concise source files with explicit typed variables, node declarations, and direct compiler errors for unknown syntax.

#import "kryon.h"

Counter :: (state: *CounterState) {
    col {
        Text("Count: " + to_string(state->n))
        Button("Increment") {
            state->n += 1
        }
    }
}

Clean, readable C99 output

The compiler emits normal C and generated headers you can read, step through, and ship with any C toolchain. Kryon-to-Kryon calls use compile-time modules; C interop stays explicit.

void Counter(CounterState *state) {
    UIPushColumn();
    Text(StringConcat("Count: ",
                      ToString(state->n)));
    UIButton("Increment");
    UIPop();
}

Live preview in Krait

Edit a .kry file and see the running app update inside the IDE. Krait compiles to an app host, loads it into the embedded viewport, and keeps preview state across reloads.

# edit app.kry, save, watch it reload
$ krait --dev run my-app

Source-aware inspection

Preview widgets carry source metadata, so an inspection click selects the generated UI element and opens the exact .kry line. The tree is the inspector.

Why Kryon

Native first, alive by default

Everything visible is a node. Source stays primary. The runtime is small, predictable, and direct — raylib-style C with no hidden translation layers.

Alive by default

Live preview, hot reload, and source-aware inspection are part of the runtime — not a bolted-on dev server.

Everything is a node

Source, bounds, state, focus, and inspection all belong to the widget tree. One model for the whole UI.

Source stays primary

.kry files own screens and reusable UI pieces. C is the generated interop target, not the authoring language.

Small native surface

Only exported functions enter generated headers, so build boundaries stay tiny and dependency-free.

Predictable runtime

Direct C, raylib-style calls, and a clear frame pipeline: build, reconcile, layout, input, update, render, overlays.

Real product UI

Layout, text, inputs, navigation, overlays, inspection, themes, and runtime assets — covered out of the box.

Readable C99

What you write is what you ship

No opaque IR, no bundled VM. Kryon compiles .kry into plain C you can read and debug — the generated output looks like code you would have written by hand.

app.krysource
#import "kryon.h"

Greeting :: (name: string) {
    row {
        Icon(ICON_ROCKET)
        Text("Hello, " + name)
    }
}
app.cgenerated
#include "app.h"

void Greeting(string name) {
    UIPushRow();
    UIIcon(ICON_ROCKET);
    UI(Text(StringConcat("Hello, ", name)));
    UIPop();
}

Get started

Build the runtime and tools

Kryon is free and open source. Clone, build, and install in a few commands.

Build the runtime:

git clone https://github.com/kryonlabs/kryon.git
cd kryon
make
make install

A simple .kry shape:

#import "kryon.h"

AppHome :: (app: InbeApp*) {
    y: int = ScaleUIPx(24)

    Text("Inner Breeze", ScaleUIPx(20), y, UI_TEXT_24)
    BottomNav(app->bottom_nav)
}

Open a project in Krait:

git clone https://github.com/kryonlabs/krait.git
cd krait
gmake run ARGS=/path/to/project

FAQ

Questions

What is Kryon? ›

Kryon is a native app development stack built around .kry source files, a small runtime, declarative widget nodes, and clean translation to human-readable C99. You write intent; the runtime handles the UI lifecycle.

How is Kryon different from Flutter? ›

Flutter ships a Dart VM and its own rendering layer. Kryon compiles to plain C99 you can read and step through, with no bundled runtime VM and a raylib-style native surface. The same source targets desktop, mobile, browser, and embedded.

How is it different from Godot's UI? ›

Godot is a game engine with UI controls. Kryon is a dedicated app UI runtime — the widget tree owns layout, input routing, focus, overlays, and source-aware inspection for building product interfaces, not just game HUDs.

What is a .kry file? ›

A concise declarative source file describing pages and reusable widgets with explicit typed variables and node declarations. The compiler reports direct errors for unknown syntax, and translates each file into readable C99.

Is Kryon free? ›

Yes — Kryon and Krait are free and open source, developed by Kryon Labs. Clone and build from github.com/kryonlabs/kryon.

What platforms does it support? ›

Linux, Windows, macOS, Android, the browser via WebAssembly, and FreeBSD — including embedded targets. One interface source builds for all of them.

What is Krait? ›

Krait is the standalone first-party Kryon IDE — project workspace, .kry source editing, live preview, diagnostics, and source-aware inspection. It's built as a Kryon app. See krait.kryonlabs.com.
