What is Kryon?

Kryon is a native app development stack built around .kry source files, a small runtime, declarative widget nodes, and clean translation to human-readable C99.

The runtime owns the UI lifecycle: build the widget tree, reconcile state, layout nodes, route input, update behavior, render base widgets, then render overlays. The source describes intent; the runtime handles ordering, focus, inspection, and overlay behavior.

Goals

Native Cross-Platform

One source model for desktop, mobile, browser, and embedded targets, with platform behavior exposed as first-class Kryon features.

Readable C99

.kry translates to plain, inspectable C99 that can be built, debugged, and shipped by normal C toolchains.

Full Native UI

The widget tree should cover real product interfaces: layout, text, inputs, navigation, overlays, inspection, themes, and runtime assets.

Live Development

The runtime should support source-aware preview, diagnostics, inspection, and app reload workflows without changing the app API.

Current Status

Declarative Nodes

Kryon has moved widget-facing APIs to node declarations such as UIButtonNode, UITextNode, and UIDropdownNode.

Runtime Phases

Generated apps run a frame pipeline for tree build, reconciliation, layout, input routing, update, render, overlays, and focus cleanup.

Private Renderers

Low-level widget drawing now lives behind internal DrawUI* functions so application code uses the declarative surface.

System Themes

The runtime can sample host theme colors, respect light and dark modes when the platform exposes them, and still fall back to bundled palettes.

Core Features

Declarative .kry

Pages and reusable widgets stay in concise source files with explicit typed variables, node declarations, and direct compiler errors for unknown syntax.

Clean C Output

The compiler emits normal C and generated headers. Kry-to-Kry calls use compile-time modules, while C interop stays explicit.

Runtime UI Lifecycle

The runtime owns layout, input routing, focus, overlays, rendering order, and node measurement through inspectable widget state.

Source-Aware Inspection

Preview widgets carry source metadata, so inspection clicks select the generated UI element and open the exact .kry line.

Philosophy

  • Everything visible is a node - source, bounds, state, focus, and inspection all belong to the widget tree.
  • Source stays primary - .kry files own screens and reusable UI pieces; C is the generated interop target.
  • Tooling is source-aware - generated code, preview hosts, inspection, diagnostics, and search stay tied to .kry files.
  • Default private API - only exported functions enter generated headers, keeping build boundaries small.
  • Native first - direct C, raylib-style calls, and predictable runtime behavior across targets.

Get Started

Build the runtime and tools:

git clone https://github.com/kryonlabs/kryon.git
cd kryon
make
make install

A simple .kry shape:

#import "kryon.h"

AppHome :: (app: InbeApp*) {
    y: int = ScaleUIPx(24)

    UITextNode("Inner Breeze", ScaleUIPx(20), y, UI_TEXT_24, GetThemeText())
    UIBottomNavNode(app->bottom_nav)
}
